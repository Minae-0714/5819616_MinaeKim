# 결과 분석 
### ▪ Interpolation Search가 Binary Search보다 적게 비교하는 이유를 설명
 Binary Search의 탐색 방식
탐색 원리: 배열의 중간 위치를 기준으로 탐색을 수행합니다.

정렬된 배열에서 중간 요소를 확인한 뒤, 목표값과 비교해 탐색 범위를 절반으로 줄이는 과정입니다.
탐색 범위 축소는 등분(반씩 나누는) 방식으로 이루어지므로, 데이터 분포에 관계없이 **O(log N)**의 성능을 가집니다.
한계: 데이터가 균일하게 분포되지 않은 경우에도 중간값 기준으로 탐색하므로, 비교 횟수가 최적화되지 못할 수 있습니다.

 Interpolation Search의 탐색 방식
탐색 원리: 데이터가 균일한 분포를 가진다고 가정하고, 목표값이 배열의 어느 위치에 있을지 비율 계산을 통해 예측합니다.

![](/interpolation.png)

low와 high는 현재 탐색 범위의 시작과 끝 인덱스입니다.
배열의 값이 선형적으로 증가한다고 가정하여, 목표값의 예상 위치를 비율로 계산합니다.
장점: 목표값이 배열에서 특정 구간에 집중되어 있다면, 탐색 속도가 더 빠릅니다.

탐색 위치를 예측적으로 점프하므로, 필요한 비교 횟수가 줄어듭니다.
데이터가 균일 분포를 가질수록 **O(log(log N))**의 시간 복잡도를 보입니다.

데이터 분포를 활용

Interpolation Search는 목표값이 어느 위치에 있을지 예측합니다.
데이터가 균일하게 분포되어 있다면, 예상 위치에 도달하기 위해 더 적은 비교로 탐색을 완료합니다.
예를 들어, 값이 1, 2, 3, ..., 1000으로 균일하게 증가하는 배열에서, 값 800을 찾는 경우, Interpolation Search는 한 번의 점프로 거의 정확히 800 근처를 탐색합니다.
Binary Search의 비효율성

Binary Search는 데이터 분포를 고려하지 않고 고정적으로 중간값을 선택합니다.
목표값이 끝쪽에 있을수록 탐색 범위를 줄이는데 더 많은 단계가 필요합니다.

Interpolation Search의 한계
데이터가 균일하게 분포되지 않은 경우, Interpolation Search의 성능이 저하될 수 있습니다.
예: 값이 1, 2, 3, ..., 999, 100000처럼 극단적인 값이 포함된 경우, 비율 계산이 부정확해지고 비교 횟수가 증가할 수 있습니다.
정렬되지 않은 배열에서는 사용할 수 없습니다.
